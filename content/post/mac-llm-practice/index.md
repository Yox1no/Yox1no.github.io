## 为什么要跑本地 LLM

日常开发大部分时候都调在线 API，速度快、能力也够。但本地模型有几个不可替代的好处：

- **隐私**：处理个人笔记、本地文档的时候，不想把内容发出去
- **免费**：自建 Agent 或者做批量推理，调用 API 也是要花钱的
- **离线使用**：网络不好或者需要可靠兜底的时候直接切到本地
- **无审查**：部分场景（比如需要角色扮演、特定内容输出）在线模型有安全策略限制

所以我的分工是：在线 API 做主驾，本地 LLM 跑辅助任务和兜底。

## 硬件基础：我的 Mac 能跑什么

核心是 Apple Silicon 的统一内存设计——CPU 和 GPU 共享同一块内存池。对 LLM 推理来说，这就意味着你能把模型参数直接放在"显存"里，不需要 CPU-GPU 拷贝。24/36/48GB 甚至更大内存的 M 系列芯片，性价比比单独搞一张 24GB 显存的显卡高得多。

一般经验法则：量化后每 1B 参数大概需要 0.5-1GB 内存（取决于量化等级）。所以：

- 16GB 内存：差不多能跑 7-13B 量化模型
- 24-36GB：能跑 20-35B 量化模型
- 48GB+：能碰密集版 30-70B

这部分可以参考 Hugging Face 社区 MLX 模型页面的用户实测，以及 r/LocalLLaMA 上其他 Apple Silicon 用户的反馈。数值因具体模型、量化方案和上下文长度而异，但这个区间够建最初印象了。

## 我的模型选择和实际数据

经过反复试，目前本地留了这两个：

**Qwen3.6-27B MLX（官方版）**
- 日常用来做需要深度理解的任务
- FP16/mlx 格式，温吞但思考质量扎实
- 实测 13 tok/s

**Qwen3.6-35B-A3B Heretic MLX 4-bit（社区量化的 MoE 版本）**
- MoE 结构只有 3B 激活参数，推理特别快
- 实测 53 tok/s，不需要等待
- 适合自动 Agent、工具调用、快速生成场景
- 没审查限制

用一套自己设计的 9 维度基准（编码 / 角色扮演 / Agent / 逻辑 / MoE-专家路由 / NSFW / 指令遵循 / 推理 / 视觉）跑了测试：

| 模型 | 综合评分 | tok/s |
|------|---------|-------|
| Qwen3.6-27B MLX | 91分 | 13 t/s |
| Qwen3.6-35B-A3B Heretic MLX 4-bit | 79分 | 53 t/s |

在实际 Agent 场景里跑了一批真实任务后，感觉和这个分数基本吻合。

## 格式之争：从 GGUF 到 MLX

开始我也用 GGUF，Llama.cpp 生态确实成熟，社区人多，模型也多。但换 MLX 之后发现有明显优势：

- **首 token 速度**：MLX 比 GGUF 快约 36%
- **Agent 稳定性**：多次连续工具调用的场景下，MLX 更不容易炸上下文
- **视觉模型**：MLX 的视觉推理支持明显比 GGUF 成熟

这个结论和 HuggingFace MLX 社区讨论区/Reddit 上的基准帖是大致吻合的。LM Studio 从 v0.3.4 开始也直接支持 MLX 加载了，目前生态基本无需自己搞代码。

如果你还在 GGUF 阶段，建议至少拿一两个你常用的模型转换到 MLX 跑下来做个前后对比。很可能就不想回去了。

## 上手流程

日常用 LM Studio 加载模型，可视化管理。写 Agent 时通过 Hermes Agent 切换 `/model lmstudio` 调用本地。

实际流程很简单：
1. 去 HuggingFace 搜 `qwen` + `mlx`，找对应的模型仓库
2. 下载到 LM Studio 的模型目录
3. 日常用 LM Studio 启动 API 服务
4. Hermes 里 `/model lmstudio` 切换过去

两个模型根据场景换着用——深度推理用 27B 的，Agent 工具调用或批量生成就用 MoE 的。

## 踩坑记录

**不要盲目追大模型**。最开始我下过 Qwen3.6-35B 的全参数量化版本，单个请求生成 10 秒才出第一个 token，内存也吃紧。换成 MoE 版本差距很大——尺寸小了非常多，但日常 Agent 的操作差别不大。

**GGUF→MLX 真香**。迁移的时候我把常用模型对半分两组，同样提示在两种格式上各跑了 10 次，MLX 的首 token 延迟和中位生成速度都更稳。

**多服务场景的显存管理**：同时跑 LM Studio + 别的工具（比如 Stable Diffusion 之类）的时候，4-bit 量化模型基本不受影响，但 27B 的 FP16 版本内存占用就明显。建议日常运行的时候只保留一个本地模型在线。

## 总结：谁适合在 Mac 上跑 LLM

**适合的人：**
- 已经在 Mac 工作流里干活、不想多搞一台 Linux 机器的开发者
- 需要离线可用、隐私优先的本地推理能力
- 想低成本试试 MLX 生态的 LLM 玩家
- 想搞 Agent 开发但预算有限

**不太适合：**
- 主要需求是跑超大模型（70B+）且不能接受量化损失
- 需要极限吞吐的生产推理——Mac 在这一点上拼不过 3090/4090 集群

最后给你的建议：**先搞清楚自己的需求，再对着 Mac 的硬件上限选模型。** 脑子清楚你不会纠结到底要下载多少个模型，直接挑一两个最适配的，日常就能用了。
